# 前端需求影响分析

## 调用与范围

保留显式调用模式：用户明确调用本技能或要求按本技能分析时使用。任务只要求影响分析时不改业务代码；用户同时授权实现时，分析完成后可继续其请求，不额外设置固定批准步骤。

## 基于代码建立影响矩阵

先读需求及目标项目的路由、导航、页面、API 客户端、权限和本地化组织方式。发现已有实现时区分直接复用、局部修改和新增，不把假设路径写成已存在文件。

围绕每项用户行为列出页面入口、现有或拟建文件、变更内容、接口和权限依赖。检查新增与编辑回填、表单提交、预览、加载/错误/空态之间是否同步。无关层面不填空表占位。

SPA 新路由还需检查直接访问或刷新时的服务器回退、路由白名单和部署子路径。不能只确认客户端导航可达。

后端仅列真实接口或托管依赖，说明契约缺口和配合事项，不无故扩展成后端设计。未核实的权限码、接口或路径标为待确认，并给出需要核查的位置。

## 交付

按 [影响清单模板](templates/feature-impact.md) 裁剪输出：需求摘要、行为与文件映射、依赖顺序、阻塞问题。文件路径相对目标项目；输出位置沿用用户要求或仓库惯例。建议实现顺序以依赖和可验收行为为依据，不默认重新搭建前端工程。
