# 后台操作说明与引导

## 根据疑问选择呈现方式

先读页面、接口和实际业务条件，确认使用者是谁、在哪一步犹豫。不要用长篇帮助文档覆盖一个可通过就地提示解决的问题。

| 用户疑问 | 适合的引导 |
| --- | --- |
| 为什么看到这些记录 | 列表附近解释进入条件、筛选范围和排序 |
| 选这个有什么变化 | 选项旁说明效果、适用条件和限制 |
| 点下去会发生什么 | 确认框说明对象、影响范围及能否恢复 |
| 多个步骤怎么配合 | 按需展开的流程指南或决策树 |

## 文案必须对应真实规则

使用业务语言描述状态和结果，避免直接展示数据库、字段名、内部枚举或数组下标。用户确需填写技术参数时才解释其含义和映射。

保留筛选的 AND/OR、时间范围、阈值边界和权限条件；不能把复杂条件简化成语义错误的“全部”或“自动”。批量操作说清作用于勾选项、当前页还是全部筛选结果。

确认文案应回答对象、数量或范围、后果、可恢复性；按钮用明确动作。普通可逆操作不滥加确认。规则与代码不一致时先说明实际差异，不能自行编造理想行为。

## 落地与检查

复用现有组件和本地化约定，短说明放在决策发生处，跨步骤内容按需展开。不要通过新增卡片、线框或重复标题堆叠信息。

用典型操作走查：首次使用者能否解释记录来源、预测选择结果、判断操作影响；检查文案是否与真实筛选、空态、权限及批量范围一致。整体布局与视觉改造只在用户要求时展开。
