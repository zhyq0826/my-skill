# 表格转结构化配置

## 先明确输入与消费契约

读取实际工作表和目标配置的 schema、消费代码或可信样例，再确定工作表、标题行、有效数据范围、字段类型、排序及唯一键。不能根据表格外观猜测奖励类型、槽位编号或结束行的业务含义。

列映射、枚举表、引用 ID 和特殊行规则来自当前任务材料；将其作为显式配置，不复用其他业务的硬编码。目标契约缺失且会改变含义时先指出具体缺口。

## 转换中保留语义

- 区分空白、零、缺失、不适用和结束标记；不默认把所有空单元格变为零。
- 保留标识符的前导零和大整数精度，金额及小数按目标精度转换，不用浮点误差改变配置。
- 数量 N 表示一个对象的 quantity=N，还是展开 N 条对象，由消费者决定，不能自行选择。
- 合并单元格是否向下填充、公式是否使用缓存值需明确；公式缓存缺失或过期不能当作有效结果。
- 引用外部类型或 ID 时校验映射是否完整、是否允许禁用项；缺失映射不得静默丢弃条目或生成空奖励充成功。

## 可追溯校验

生成过程中保留工作表与源行到输出对象的映射，可放在独立校验报告中，不向不允许额外字段的目标 JSON 强塞来源信息。

检查类型、必填、枚举、唯一键、顺序/连续性（仅契约要求时）、引用完整性和汇总守恒。展开或过滤时分别核对源有效行数、输出条数与业务数量，不能仅靠行数相等判定正确。

先在暂存位置生成并验证，失败时保留原输出。交付配置、转换摘要及带源行的异常列表；若存在未解决条目，明确结果不完整，不能标为可发布。只生成配置不自动上传或写入生产。

确需脚本时按本次 schema 编写可重复执行的转换器，固定输入输出参数和异常策略，并用真实的边界样例验证。不要为了通用而预置任意业务枚举或跨项目共享有状态配置。
