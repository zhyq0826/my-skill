# 运营后台设计 Skill

## 概述

运营后台的核心矛盾：**信息密度 vs 认知成本**。设计目标是让运营在最短时间内完成最高频的操作，同时保证所有破坏性操作可追溯。

## 何时使用

**使用**：
- 新建运营工具页面、功能评审
- 讨论字段展示优先级、Tab 分区
- 设计权限模型、操作审计
- 评审批量操作、搜索筛选、数据导出流程

**不使用**（用其他 skill）：
- 纯 C 端用户界面设计
- API 接口设计
- 数据库 schema 设计

---

## 一、设计前必问（强制）

在动手前回答这 5 个问题，答案决定后续所有设计决策：

1. **谁用、多高频**？（决定入口深度 + 操作效率要求）
2. **最高频任务是什么**？（放最显眼的位置，不是藏在 Tab 里）
3. **最危险的操作是什么**？（封号、删帖、重置密码 → 二次确认 + 留痕）
4. **3 秒内能判断吗**？（运营打开页面 3 秒内应该能判断是否有问题）
5. **6 个月后谁来排查**？（决定操作日志字段）

---

## 二、页面形态选择

| 场景 | 推荐形态 |
|---|---|
| 查找/管理大量对象（用户、内容、订单） | **列表页 + 详情页** |
| 单对象的多维度信息 | **详情页 + Tab 分区** |
| 监控型 | **Dashboard 卡片 + 表格** |
| 配置型 | **表单页**，分 Section |

## 三、列表页设计（最高频形态）

### 3.1 搜索与筛选区

**必须有**：主搜索框（支持多类型，如 MID / 手机号 / 昵称）

**筛选器布局原则**：
- 高频筛选（状态、时间范围）：始终展示
- 低频筛选（注册来源、设备类型）：「更多筛选」折叠
- 当前已激活的筛选条件必须以 Tag 形式展示在搜索栏下方，支持单独删除

**禁止**：一次性把 10 个筛选项全量展示；搜索后不展示命中条数。

### 3.2 列表列设计

| 列 | 原则 |
|---|---|
| 状态列 | 永远在左侧第 2-3 列；用彩色徽章（见颜色语义章节） |
| ID 列 | 等宽字体；支持复制按钮 |
| 时间列 | 固定宽度；Hover 显示精确时间戳 |
| 操作列 | 固定在最右侧；只放 1-2 个高频操作，其余放「更多」下拉 |

**超出行数**：超 20 条必须分页（无限滚动仅适合流式内容）。

### 3.3 空状态处理

| 原因 | 提示内容 |
|---|---|
| 搜索无结果 | "未找到符合条件的结果" + 建议修改筛选 |
| 无权限 | "暂无查看权限，请联系管理员" |
| 接口超时 | "数据加载失败" + 重试按钮 |
| 数据为空 | 明确说明原因，不留空白页 |

## 四、详情页信息架构

### 4.1 三层展示原则（结论优先，细节按需）

```
第一层（永远可见）：身份 + 核心状态 + 异常信号
第二层（Tab/展开）：分类详情（风控、内容、账号安全、设备）
第三层（折叠/弹窗）：原始数据、完整 JSON、历史日志
```

永远不要把「账号状态」「是否封禁」「风控等级」埋在第二层或更深处。

### 4.2 「用户身份头卡」必须包含

| 元素 | 说明 |
|---|---|
| 用户 ID（MID） | 首要标识，等宽字体，大号展示 |
| 昵称 | 注意 overflow，长串截断 + tooltip |
| 头像 | 有助于快速识别真实账号 vs 机器人 |
| 账号状态徽章 | ACTIVE / 封禁 / 注销，颜色编码 |
| 风险等级徽章 | LOW RISK / CHALLENGE / HIGH RISK |
| 关键字段横排 | 手机号（脱敏）、注册时间、最后登录（4～6 个，不超过） |

**禁止**：头卡堆超过 8 个字段；无视觉层次的纯文本列表。

### 4.3 Tab 分区原则

每个 Tab 代表一个独立「视角」，不是「信息的碎片」：

| Tab 名 | 聚焦问题 |
|---|---|
| 概览 | 这个用户整体是谁？ |
| 内容 | 他发了什么？有问题吗？ |
| 风控与信用 | 他的风险画像如何？ |
| 账号安全 | 他用什么设备？有没有异常登录？ |
| 操作日志 | 对这个用户做过哪些操作？ |

**反模式**：把「注册风控流水」和「信用档案」拆到两个不相关的 Tab。

## 五、操作设计

### 5.1 破坏性操作（封号、删帖、重置密码）

必须同时满足：

- [ ] 二次确认弹窗（带操作摘要，不是"确定吗？"），需填写 reason
- [ ] 操作人自动归因（`operator` 字段，取当前登录运营账号）
- [ ] 后端写入操作日志（`created_by`、`reason`、`timestamp`、`before_state`）
- [ ] 成功后页面局部刷新 + 明确的成功 Toast（不能整页跳走）
- [ ] 操作管理员可在操作日志 Tab 中查阅

### 5.2 批量操作

适合：批量封禁、批量审核通过、批量导出

设计要点：
- 列表页顶部展示「已选 N 条」 + 批量操作按钮区
- 超过 50 条时，支持「全选当前搜索结果（共 N 条）」的跨页全选
- 批量破坏性操作必须有「批量确认弹窗」，展示操作摘要（选中 N 条，预计影响 M 用户）
- 执行结果需返回成功/失败明细（失败条目可导出排查）

### 5.3 操作反馈与加载状态

| 场景 | 正确处理 |
|---|---|
| 提交操作中 | 按钮变 loading，禁用表单，防止重复提交 |
| 操作成功 | Toast 成功消息（3s 自动消失）+ 局部刷新相关数据 |
| 操作失败 | Toast 错误消息 + 错误详情（不是"请求失败"这种无用信息） |
| 页面初始加载 | Skeleton 占位，而非空白 + Spinner |
| 列表刷新中 | 保持当前内容可见，顶部加细 loading 条 |

**禁止**：操作后静默失败（无任何反馈）；整页刷新（丢失筛选条件）。

### 5.4 未实现操作的处理

未开发的操作按钮不要 `disabled` 堆在界面上。选择其一：
- **不渲染**（功能未规划则移除）
- **隐藏在「更多操作」折叠里**（功能已规划但未实现）
- **显示 tooltip 说明"即将上线"**（已排期且运营需要知晓）

## 六、数据导出设计

运营后台几乎必须支持导出。设计要点：

- 导出范围：当前筛选结果（不是全库），上限建议 10 万条，超出时提示分批导出
- 导出格式：Excel（`.xlsx`）为主；CSV 作为可选
- 导出字段：不要全字段导出，提供字段选择器（默认勾选常用字段）
- 导出进度：超 1 万条时异步导出，下载中心 / 邮件通知
- 权限：导出操作记录「谁在什么时间导出了什么条件的数据」（合规要求）
- **禁止**：直接暴露手机号、身份证明文到导出文件（需脱敏或申请审批）

## 七、风控/内容页面特殊要点

### 7.1 风险信号「置顶提示条」

命中风控规则时，在头卡下方、Tab 上方展示：
- 非弹窗形式（不打断操作流）
- 圆角块，浅色底（非刺眼红/黄 Alert）
- 展示：触发规则名、分值、来源 IP / 设备

### 7.2 账号处置状态展示

封禁类字段（静默/禁言/禁发帖/禁评）用**网格块**而非 `Descriptions` 表格：
- 2～3 列响应式
- 每个格子：标签（uppercase 小字）+ 值（medium 字重）
- 异常值（≠0）用主色或红色强调

### 7.3 内容列表

- 每条帖子：封面图缩略图 + 标题 + 状态标签 + 审核结果 + 发布时间
- 支持点击跳转内容审核工作台（带预填参数）
- 超过 20 条必须分页

## 八、权限与安全

### 8.1 读写权限分级

```
只读权限：可看所有信息，不渲染任何写操作按钮（不是 disabled，是不渲染）
写权限：渲染按钮，按钮可用
超管权限：才能看到「封号」「重置密码」等高风险操作
```

### 8.2 安全设计清单

- [ ] 该页面/接口有角色权限控制（RBAC）？
- [ ] 读操作和写操作是否拆分为独立权限码？
- [ ] 写操作是否通过代理层注入 `operator` 上下文？
- [ ] 操作日志写入后端（不只是前端 Toast）？
- [ ] 手机号/身份证等敏感字段脱敏展示？（`138****5678`）
- [ ] 分页接口有合理的最大 `page_size` 限制（建议不超过 200）？
- [ ] 导出操作有审计日志？

## 九、颜色语义系统

| 颜色 | 语义 | 典型用途 |
|---|---|---|
| 绿色 | 健康/正常/通过 | ACTIVE 状态、低风险、审核通过 |
| 蓝色（主色） | 中性信息/主操作 | 主按钮、MID 字段 |
| 黄/橙色 | 警示/待处理 | 待审核、CHALLENGE 风险 |
| 红色 | 危险/异常 | 封禁状态、高风险、破坏性操作 |
| 灰色 | 禁用/次要/空值 | 禁用按钮、`—` 占位、次要文字 |

**禁止**：把红色用于"普通强调"；把绿色用于"只是好看"。

## 十、设计完成标准（DoD）

一个运营后台页面「完成」的标准：

| 标准 | 验证方式 |
|---|---|
| 3 秒判断 | 运营打开页面 3s 内能判断用户/内容是否有问题 |
| 零歧义 | 所有字段有 label，空值显示 `—` 而非空白 |
| 操作可追溯 | 破坏性操作有 `reason` + 操作日志，管理员可查 |
| 权限隔离 | 无写权限时，页面不渲染（不是 disabled）写操作入口 |
| 空状态友好 | 无数据时显示原因（无数据 / 无权限 / 接口超时） |
| 错误可见 | 接口失败有明确提示，不静默失败 |
| 搜索无损 | 操作成功后，搜索筛选条件不丢失 |
| 批量有明细 | 批量操作返回成功/失败明细，失败可导出排查 |
