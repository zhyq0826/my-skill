# 评价框架

## 证据状态

| 状态 | 含义 | 处理 |
| --- | --- | --- |
| 已证明 | 具体案例和个人动作经追问支持 | 按岗位标准评价 |
| 部分证明 | 有相关回答，但深度、边界或贡献未充分验证 | 说明已证明部分与缺口 |
| 反向证据 | 回答出现实质错误或与声明不符 | 说明岗位影响，必要时交叉核实 |
| 未验证 | 未问到、记录缺失或无法判断 | 标为未验证，不记零分 |

证据状态与置信度分开。一个案例可以证明局部能力，但不足以支持对全部岗位能力的高置信度判断。面试官提示后的复述不等同于独立解决问题。

## 评分

优先使用用户提供的岗位量表。没有量表时，可用以下五分制作为解释锚点，并按岗位级别调整具体证据要求；不预设通用录用分数线。

| 分数 | 锚点 |
| --- | --- |
| 5 | 超出岗位要求，有复杂实践、权衡和可验证成果，能指导他人 |
| 4 | 稳定满足要求，能独立完成工作并处理主要异常 |
| 3 | 基本满足常规要求，但复杂边界或长期维护经验有限 |
| 2 | 部分相关，关键实现、失败处理或个人贡献不足 |
| 1 | 有明确证据显示核心能力不符合要求 |

只在有证据的维度评分，避免假精确的小数。若使用加权分：

```text
综合分 = Σ(已评分维度得分 × 该维度权重) / Σ(已评分维度权重)
证据覆盖率 = 已评分维度权重之和 / 全部维度权重之和
```

分母为零时不计算综合分。部分证明虽可评分，但仍应单列其证据缺口；覆盖率不等于能力水平。不同候选人的覆盖范围不同，不能只比较总分。硬门槛未验证时给条件性建议；硬门槛明确不满足时不能用加分项抵消。

## 问题设计

每题写清考察能力、主问题、必要追问和评价锚点。追问优先围绕：本人具体做了什么、为什么选择该方案、边界和失败如何处理、结果如何验证。避免通过提示不断替候选人补齐答案。

规模类指标区分用户量、请求量、吞吐和峰值；性能改善区分平均值、尾延迟、负载与资源成本。经历复盘评估可核实贡献，实作题评估完成过程，两者不能互相冒充。

## 面后输出

先给岗位匹配结论与置信度，再列核心维度的证据、优势及风险。区分能力不足与未验证，只提出影响结论的补充验证。候选人信息仅保留评估所需内容，不在公共示例中暴露个人资料。
