# 技术岗位能力参照

用于选择岗位相关的评价维度，不是所有技术候选人的必考题库。以实际 JD 和职责为准，必要时只取几个维度。

| 岗位方向 | 优先验证的内容 | 有区分度的证据 |
| --- | --- | --- |
| 后端 | 业务建模、接口与数据一致性、并发、性能与稳定性 | 真实调用链、事务边界、幂等与失败恢复、容量与性能验证 |
| 前端 / 客户端 | 状态与交互、异步数据流、性能、兼容性与发布质量 | 复杂交互的状态设计、竞态与异常处理、性能定位、回归和线上问题 |
| 测试 / 质量 | 风险分析、测试设计、自动化与问题定位 | 如何选关键路径、发现边界缺陷、减少误报、支持发布判断 |
| 数据工程 | 数据建模、批流处理、质量、一致性与成本 | 延迟与吞吐口径、重放补数、重复与丢失处理、数据核对 |
| 算法 / AI | 问题定义、数据与实验、评估、部署和迭代 | 基线对照、数据泄漏防范、离线线上差异、质量与延迟成本权衡 |
| 基础设施 / SRE | 可用性、可观测性、容量、自动化与故障治理 | 事故时间线、恢复决策、容量证据、告警效果、长期改进 |
| 技术负责人 | 技术决策、跨团队边界、交付与质量、人才培养 | 亲自作出的取舍、组织约束、落地结果及长期技术责任 |

## 校准深度

初级侧重在指导下正确完成任务、理解基础和定位常见问题；中级侧重独立负责模块及异常闭环；高级侧重复杂约束、跨模块权衡和长期演进。负责人岗位增加团队和组织层面证据，但不能用带人数量替代技术判断。

这些只是出题深度参照，不是统一职级标准。年限不能直接转换成等级；小规模业务同样可能有复杂约束，不因缺少“大厂高并发”经历一概降档。

## 横向核实

- 工具名转为机制问题：候选人具体使用、配置、改造或排障过什么。
- 项目成绩转为归因问题：本人动作、基线、对照、观察窗口和副作用。
- AI 辅助编码转为工程责任问题：如何理解生成代码、验证行为、排查失败和维护结果，不因使用 AI 直接加分或扣分。
- 开放设计题关注约束澄清和方案演进，不以答案是否命中面试官偏好判分。
